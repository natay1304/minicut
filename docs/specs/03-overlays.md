# minicut v3 — несколько оверлей-дорожек (до 10)

Сейчас в проекте две дорожки: `main` и `overlay`. Нужно до **10** оверлей-дорожек. Всё, что умеет UI, доступно и через `/api/op`, и через MCP. Старые проекты (`main` + `overlay`) должны открываться без изменений.

Читай SPEC.md и SPEC2.md для контекста. Ограничения те же: только localhost, без сборщиков, vanilla JS.

## Модель данных
- Дорожки: `main` (ripple) и оверлеи с id `overlay`, `overlay2`, `overlay3` … `overlay10` (kind `free`). Максимум 10 оверлеев.
- Порядок в `tracks`: `main`, затем оверлеи по номеру (`overlay` = номер 1). Номер = z-порядок: больший номер рисуется поверх меньшего, все оверлеи поверх `main`.
- В проекте всегда есть `main` и минимум один `overlay`. Остальные создаются по требованию.
- Нормализация при загрузке (`normalizeProject` в src/ops.js): читать все дорожки с id по шаблону `^overlay(\d+)?$` (номер 1..10), сортировать по номеру, неизвестные id игнорировать. Старые проекты с одним `overlay` работают как раньше.

## Операции (src/ops.js, все с undo/redo, как существующие)
- `trackOf` принимает `main` и `overlay`, `overlay2`..`overlay10`. Если дорожки с таким номером ещё нет, **создать её автоматически вместе со всеми промежуточными** (addClip на `overlay4` создаёт `overlay2`, `overlay3`, `overlay4`). Номер вне 1..10 → понятная ошибка «Максимум 10 оверлей-дорожек».
- `addOverlayTrack()` — добавить следующую дорожку, вернуть её id. На 10 бросает ошибку.
- `removeOverlayTrack(id)` — удалить дорожку, только если она пустая и это не `overlay` (первая). Иначе ошибка с причиной.
- `moveClipToTrack(clipId, track, start?)` — перенести клип между оверлеями (или `main` ↔ оверлей, если сейчас возможно: при переносе в `main` клип добавляется в конец, при переносе в оверлей `start` по умолчанию = текущая позиция клипа на таймлайне). Сохраняет in/out/scale/x/y/volume/fade/name.
- Существующие операции с аргументом `track` работают для любой оверлей-дорожки (`setClip`, `trim`, `remove`, `split`, `splitAt`, `setClips`, `removeClips` ищут клип по id во всех дорожках, как сейчас).
- `splitAt(timelineTime, track)` по умолчанию режет `main`; для оверлея без аргумента не должен трогать чужие дорожки.
- Длительность проекта и индикатор конца таймлайна учитывают клипы всех дорожек.

## Рендер (src/ops.js plan + src/ffmpeg.js)
- В плане `overlays` — клипы всех оверлей-дорожек, в порядке дорожек (меньший номер раньше, поверх накладывается больший). `buildGraph` уже умеет цепочку overlay; убедись, что для десяти дорожек и множества клипов:
  - входы и метки уникальны (`ov`/`oa` индексы сквозные);
  - звук оверлеев с `muted:false` смешивается через `amix` (normalize=0, как сейчас);
  - превью-рендер (`/api/preview`) работает так же.
- Для проверки сделай маленький тест в `data/` (не коммить): 3 оверлея на разных дорожках, пересекающиеся по времени, `scale 0.4` и разные `x/y`, рендер 540×960, ffprobe показывает нужную длительность, кадры (ffmpeg `-ss` + `-frames:v 1`) показывают все три врезки одновременно.

## MCP (src/mcp.js)
- Параметр `track` везде: строка `main` или `overlay`..`overlay10` (z.string с описанием; валидировать на сервере).
- Новые тулы: `add_overlay_track`, `remove_overlay_track`, `move_clip_to_track`.
- `get_project` возвращает все дорожки.

## UI (public/)
- Таймлайн: отдельная строка для каждой дорожки. Сверху вниз как в монтажках: самый верхний оверлей сверху, `main` снизу. Слева у каждой строки подпись (`V1` для main, `O1`..`O10` для оверлеев) и у пустых оверлеев кнопка «×» (удалить дорожку; первая `O1` не удаляется). Строки нужной высоты, таймлайн скроллится по вертикали при 5+ дорожках, линейка и плейхед остаются на месте.
- Кнопка «+ Дорожка» рядом с зумом/добавлением: добавляет оверлей (`addOverlayTrack`), отключена на 10.
- Селект «куда добавлять» (`#add-track`) содержит все существующие дорожки.
- Перетаскивание клипа оверлея: по горизонтали меняет `start` (snap к краям клипов всех дорожек и плейхеду, как сейчас), по вертикали перекидывает на другую оверлей-дорожку (`moveClipToTrack`). Визуально подсвечивай целевую строку.
- Выделение, рамка, Shift/Cmd+клик, группа, Delete работают на клипах всех дорожек.
- Превью: сейчас один `<video id="preview-overlay">`. Нужен пул видеоэлементов, **по одному на оверлей-дорожку** (создавать динамически, z-index по номеру дорожки, все поверх main). Каждый элемент воспроизводит активный клип своей дорожки на плейхеде, учитывает scale/x/y/volume/mute/fade как сейчас. Звук не мультиплицируется: если у клипов несколько дорожек `muted:false`, играют все. Лишние элементы очищай (src убирать, `load()`), при смене проекта и при удалении дорожки.
- Холст/рамка выбора клипа в превью (если есть) работает с клипом любой дорожки; клик по превью выбирает верхний клип под плейхедом.
- Мобильная вёрстка и существующие горячие клавиши не ломать.

## Что должно быть проверено перед завершением
Запусти сервер на **другом порту**, например `PORT=4399` (проверь, как порт задаётся в src/server.js; если захардкожен, добавь чтение `process.env.PORT`, по умолчанию 4317), чтобы не трогать рабочий сервер на 4317. Остановка сервера по завершении обязательна.
Не запускай долгие команды и не трогай `data/projects/` существующих проектов: для тестов создавай проект `test-multi` и удали его в конце.
1. `node --check` для всех `src/*.js` и `public/app.js`.
2. Скрипт на curl/node: создать проект, импортировать видео из `data/test.mp4`, добавить клипы на `overlay`, `overlay2`, `overlay5` (проверить автосоздание дорожек 2..5), `moveClipToTrack`, `removeOverlayTrack` (пустая / непустая), ошибка на `overlay11`, undo/redo.
3. Рендер-тест из раздела «Рендер».

Важно: тестовый сервер использует тот же `data/`. Перед тестами запомни содержимое `data/current.txt`, а в конце верни его как было (сейчас там `pxl-narezka-2`, но запомни фактическое значение сам) и удали проект `test-multi`. Рабочий сервер на порту 4317 не останавливай и не перезапускай.
